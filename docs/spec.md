# agy — Antigravity CLI для Claude Code

## Цель
Использовать Antigravity CLI (`agy`, подписка Google AI Pro) как равноправного исполнителя рядом с Claude-агентами:
одноразовым субагентом или именованным тимейтом, к которому можно обращаться повторно.

## Решения
- Плагин `agy`, ставится через marketplace этого репозитория (или локально через `CLAUDE_CODE_PLUGIN_DIRS`). SessionStart-хук пишет стабильную точку входа `~/.claude/agy/agy-companion.mjs`.
- Две роли, от роли зависит модель и режим agy:
  | Роль | Режим agy | Цепочка моделей |
  |---|---|---|
  | `code` (запись) | обычный | gemini-4-neon-medium → claude-sonnet-5-5-medium → gemini-4-argon-medium |
  | `review` (анализ/ревью, чтение) | `--mode plan` | gemini-4-neon-medium |
  | `recon` (разведка, чтение) | `--mode plan` | gemini-4-hydrogen-medium → claude-sonnet-5-5-low |
  Разведка — разовые вызовы, вопросы пачкой; одиночный grep делается локально, при пустой квоте — Claude haiku.
- Каждый вызов agy идёт с `--dangerously-skip-permissions`. Глобальные настройки agy не трогаются.
- Квота: `agy -p /usage --output-format json` (0 токенов) перед вызовом, кэш 60 с.
  Группы: `gemini` (Neon, Flash; 5ч + неделя), `3p` (Claude, GPT-OSS; 5ч + неделя), `argon` (неделя).
  Модель пропускается, если любой лимит её группы < 5%. Ошибка квоты от agy помечает группу исчерпанной до её reset_time.
  Квота кончилась посреди сессии → та же сессия (`--conversation`) продолжается на следующей модели цепочки.
  Все модели роли исчерпаны → `QUOTA_EXHAUSTED` + время ближайшего сброса; работа уходит Claude-агентам.
- Ядро `scripts/agy-companion.mjs` (Node, без зависимостей): квоты, выбор модели, реестр именованных сессий
  (`name → conversation_id`), фоновые задачи (лимит хода 120 мин; ход, упёршийся в лимит, продолжается в том же разговоре), status/result/cancel.
  Состояние: `~/.claude/agy/` (quota.json, sessions.json, jobs/).
- Команды: `/agy:run`, `/agy:ask`, `/agy:status`, `/agy:result`, `/agy:cancel`, `/agy:usage`.
- agy-агенты — обычные агенты Claude Code: мод `hooks/agy-agents.ts` добавляет типы `agy:code|review|recon`, хук `turn.step` отвечает за модель запуском agy (живой ход работы — как thinking), служебные кадры команды (task_assignment, idle) agy не будят, shutdown_request одобряется штатным SendMessage. Запасной путь без списка агентов — `team spawn` (файловый протокол команды).
  Ждёт задачу порциями по 9 мин (лимит Bash 10 мин).
- Скилл `agy:antigravity` — когда и как отдавать работу agy. Проактивно везде.
  agy — равноправный исполнитель; как «второе мнение» — только по прямой просьбе пользователя.
- teamlead:
  - делегируемая работа (код, ревью) сначала идёт в agy, пока у роли есть квота; иначе — Claude;
  - не больше 2 пишущих agy одновременно, каждый в своём worktree (`wt add`), agy коммитит сам, лид вливает по `sdd.md`;
  - вне git — общая копия с закреплёнными файлами;
  - финальная приёмка и задачи, завязанные на решения из разговора, — только Claude;
  - убраны лимиты «3 пишущих» и «5 агентов всего»; `test-lock` остаётся;
  - watchdog смотрит и на задачи agy (`agy-companion status`).
- Тесты: логика квот и цепочек — на заглушке `AGY_BIN`; живые проверки — на `gemini-3.8-flash-low`.

## Наблюдения о agy 1.5.11
- `-p` берёт следующий аргумент как промпт; stdin не читается. Длинный промпт → файл + короткая ссылка на него.
- В Git Bash `/usage` нужно `MSYS_NO_PATHCONV=1` (из Node spawn без шелла — не нужно).
- Минимальный вызов ≈ 12k входных токенов (большой системный промпт): мелкие задачи в agy невыгодны.
- `--mode plan` на вопрос-анализ отвечает текстом; на задачу с правками — пишет план и просит одобрения.
